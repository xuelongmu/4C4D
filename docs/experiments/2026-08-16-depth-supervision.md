# Depth supervision from MASt3R (issue #19)

Date: 2026-08-16

Tests whether a scale-invariant depth loss against a MASt3R prior closes the
sparse-view generalization gap on the 8-camera split (held out: 4, 6). Baseline
for both seeds is `ab8-staticfreeze`, the production profile at the top of the
enhancement stack: `--max_num_pts 1000000 --gpu_cache --freeze_static_temporal`,
`--res 2`, 7500 iterations. Depth rows add `--depth_supervision` at the default
`--lambda_depth 0.05 --depth_patch_size 32 --depth_alpha_threshold 0.5`.

## The prior

One static depth prior per training camera, generated by
`scripts/make_mast3r_depth_priors.py`:

1. Reduce each camera's 150 frames to a temporal-median background plate.
2. Mark every pixel the subject ever occupies as invalid (temporal MAD > 6/255,
   dilated 9 px). One static prior is then valid at *every* frame of that
   camera, because the pixels where it would be wrong carry no supervision.
3. MASt3R multi-view inference over the 8 plates (complete pair graph, 56 pairs)
   plus global alignment.

Result: 38–64% of pixels valid per camera, 8.2 MB total, stored outside git at
`data/Xuelong/clip_f300_5s_rgb_posefix/depth_priors/` with a provenance
manifest.

**Prior quality: Spearman 0.78** against the RGB bundle-adjusted triangulation
(`scripts/validate_depth_priors.py`, per-camera range 0.51–0.92). Pearson is
lower (0.45), i.e. the relationship is monotonic but not linear — which is
exactly the case the patch-wise correlation loss is built for.

> **Trap, documented so nobody repeats it.** Scoring the prior against
> `sparse/0/points3D` reports Spearman −0.03 and looks like total failure. That
> file is the *training initialization*: 75k synthetic "calibrated rig volume"
> points with empty TRACK entries, whose keypoint associations in `images.txt`
> are placeholders — some project behind the camera. The real triangulation is
> `rgb_init/refined` (3690 points, 9448 observations). The validator now prints
> a reprojection control (0.5–0.8 px on the correct model, ~850 px on the wrong
> one) so this failure announces itself.

Noise band on held-out is ±0.4 dB; adoption required improvement on both seeds
beyond it.

## Verdict

**Not adopted.** Held-out moved −0.41 dB (seed 42) and −0.05 dB (seed 43), mean
−0.23 dB. Neither seed improved; seed 42 sits at the edge of the noise band on
the wrong side. The flag ships off by default.

Worth noting the direction on seed 42: train PSNR *rose* (27.36 → 27.59) while
held-out fell, with 12k more gaussians. A term added as a geometric regularizer
behaved marginally like extra fitting capacity — the opposite of its purpose,
and consistent with the diagnosis below that it had no geometric error left to
correct.

## Why: the prior had nothing left to add

The depth loss is logged to TensorBoard as `train_loss_patches/depth_loss`. On
seed 43 it starts at **0.082 at iteration 100** and converges to **0.019** —
one minus a correlation, so this is not a small residual on a large scale:
i.e. rendered depth already correlates with the MASt3R prior at 0.92 within the
first 100 iterations, and at 0.98 by the end.

That is not a vacuous metric. Scoring deliberately wrong depth maps against the
same priors at the same patch size:

| "reconstruction" | patch 32 | patch 128 |
|---|---:|---:|
| shuffled noise | 1.000 | 1.000 |
| best-fit plane | 0.383 | 0.372 |
| pure x-ramp | 0.301 | 0.291 |
| **trained model** | **0.019** | — |

A plane scores 20× worse than the trained model, so the loss does discriminate
geometry. The model simply already satisfies it.

**Conclusion: depth ordering is not this scene's binding constraint.** The
calibrated rig gives accurate poses and a volume initialization, so coarse
geometry is right almost immediately. The held-out gap comes from something
else — and notably not from the region the prior covers: the prior is static
structure only, so the moving subject, which is most of the image content and
where held-out error concentrates, receives no supervision at all by
construction.

## Recommended follow-up

1. **Per-frame video depth for the dynamic subject** (the issue's stretch goal)
   is the branch worth pursuing. It targets the pixels this prior deliberately
   excludes. `utils/depth_priors.py` already prefers a per-frame
   `cam00_0042.npz` over a per-camera `cam00.npz`, so this needs a generator,
   not a training change.
2. Do not re-test static multi-view depth on rigs with calibrated poses and a
   volume initialization; the measurement above says the signal is already
   there.
3. The flag ships off by default, as `--color_affine` did for the same reason:
   the implementation is validated and cheap to enable for a rig where the
   initialization is worse than this one's.
